# KAKKEKO（仮） / 会話コンテンツ制作ツール

ブーン系小説、TRPGリプレイ、座談会、インタビュー、オモコロ系の掛け合い記事、キャラクター会話劇など、
「アイコン＋会話」を主役にして、必要なときだけ地の文・画像・見出しを挟むコンテンツを簡単に制作するWebツール。

## 開発方針

- AI機能はMVPでは実装しない
- PCファースト、スマホ閲覧は必須、スマホ編集はPhase 2以降で強化
- データ本体と見た目を分離し、同じ原稿を複数テーマへ切り替え可能にする
- 投稿サービス化を見据えるが、MVPはローカル保存＋HTML/JSON/TXT書き出しまで
- ユーザーがMarkdownやHTMLを理解しなくても使えるUI
- 「文章を書く」より「発言を積む」ことを中心にする

## 開発・起動

Node.js 22.12以降（推奨24 LTS）とnpmを使用します。

```sh
npm install
npm run dev
npm run build
npm run test
npm run lint
npx playwright install chromium
npm run test:e2e
npm run format:check
```

開発サーバーに表示されるローカルURLを開いてください。`dist/`が静的配信用の成果物です。
実装順はTASKS.mdのPhase 0〜20です。ROADMAP.mdの将来機能は別の段階として扱います。

この作業環境ではnpmがPATHにないため、プロジェクト内のnpmでも起動できます。

```powershell
node .tools/node_modules/npm/bin/npm-cli.js run dev
# この作業環境に取得済みのChromiumでE2Eを再実行する場合
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path $PWD '.tools/ms-playwright'
node .tools/node_modules/npm/bin/npm-cli.js run test:e2e
```

## 実装済みの機能

- 作品・キャラクター・エピソードの作成、編集、複製、削除、並べ替え
- セリフ・地の文・見出し・画像・区切り・非公開メモの6種のブロック
- 同じ話し手で連続入力、話者ショートカット、IME入力中の誤操作防止
- マウス・タッチ・キーボードによる並べ替え、最大100操作のUndo/Redo
- 5テーマとPC / スマホのライブプレビュー
- IndexedDB自動保存、保存失敗時の表示、全作品JSONバックアップ
- JSON入出力、3形式のTXT、画像・CSS埋め込みHTML、CSS・画像同梱ZIP
- PC3カラム、1200px未満のプレビュードロワー、800px未満の編集タブ

ホームの「サンプル作品を開く」で、同梱の `sample-project.json` を新規作品として試せます。

各画面の右上に「更新情報」「表示モード」「Help」を配置しています。
表示モードはライト・ダーク・自動（端末設定）から選べ、設定画面の外観と連動してブラウザーに保存されます。
更新情報とHelpは現在の画面に重ねて表示され、閉じるとそのまま編集を続けられます。

### 制作を続けるための補助機能

- 新規作品では「キャラクター登録→セリフ入力→プレビュー確認」の操作ガイドを表示します。閉じた後も編集画面のHelpから再表示できます。
- 作品一覧と編集画面に最終JSON出力日時と「出力後に変更あり」を表示します。記録はダウンロード開始時点です。実際に保存されたファイルも確認してください。
- 設定画面では最終全作品JSON出力の日時・作品数を確認でき、バックアップ案内を「通知しない／7日／30日」から選べます。初期状態は無効です。案内はアプリ内だけに表示されます。
- 編集画面の「作品内を検索」から全エピソードのタイトル・本文・話者名・画像の説明・編集用ノートを横断検索できます。メモ・非表示も状態を明示して検索し、結果から該当箇所へ移動できます。全角・半角と英字の大文字・小文字を区別しません。
- スマホ幅（800px未満）では作品ごとに最後のエピソード・編集ブロック・スクロール位置を記憶し、再読み込みや再オープン時に復元します。入力欄への自動フォーカスは行いません。

これらの操作ガイド・バックアップ記録・編集位置はブラウザー内の補助情報です。作品JSONのデータ形式を変更せず、他の端末には移りません。

## 使い方

1. 「新規作品」でタイトル・テンプレート・テーマを指定します。
2. キャラクターを登録し、左の一覧またはスマホの「次の話し手」で選びます。
3. 下部の追加バーで発言を追加します。キャラクターのダブルクリックでも追加できます。
4. プレビューを見ながら編集し、「書き出し」から必要な形式を保存します。

| 操作                               | ショートカット                          |
| ---------------------------------- | --------------------------------------- |
| 直後に同じ話し手のセリフを追加     | Ctrl / Cmd + Enter                      |
| 手動順1〜9のキャラで発言を追加     | Alt + 1〜9                              |
| 地の文を追加                       | Ctrl / Cmd + Shift + N                  |
| Undo / Redo                        | Ctrl / Cmd + Z / Ctrl / Cmd + Shift + Z |
| 明示保存                           | Ctrl / Cmd + S                          |
| 並べ替えハンドルをつかむ・確定する | Space / Enter                           |
| つかんだブロックを移動する         | ↑ / ↓                                   |
| ダイアログを閉じる・ドラッグを中止 | Escape                                  |

セリフ内のEnterは改行です。キャラ選択メニュー内では数字キー1〜9で選べます。
発言のあるキャラクターは完全削除できません。アーカイブすると既存の発言を保ったまま追加候補から外せます。

## 保存・書き出しについて

作品は利用中のブラウザーとオリジン（ホスト・ポート）ごとに保存されます。
サーバーやアカウントは不要です。ブラウザーのデータ削除で消えるため、作品メニューのJSON出力または設定画面の全作品バックアップを利用してください。
自動保存は初期値1.2秒、作品ごとに変更できます。失敗時は編集データを保持し、保存ボタンで再試行できます。JSON出力は未保存の最新原稿も含みます。

JSONは `schemaVersion: "1.0.0"` の作品、または作品の配列を受け付けます。
読み込み時はIDとキャラクター参照を再発行して新規作品として追加し、既存作品を上書きしません。
未知のバージョン、破損JSON、重複ID、存在しない話者参照はエラーの場所を表示します。
初版のため旧版からの変換処理はなく、将来用のマイグレーション入口を用意しています。

JSONは非公開メモ・非表示ブロックも含む完全なバックアップです。
HTML/TXTは初期状態でメモを除外し、非表示ブロックは常に除外します。HTMLには編集UI・JavaScriptを含めません。
ZIPには `index.html`（目次）、話数別HTML、`style.css`、使用画像の `assets/` を格納します。
ローカル画像はData URLで保存し、2 MiB超で警告します。外部URLの画像は書き出し時に取得・埋め込みを試みます。
CORSなどで取得できない場合は理由と対処を表示します。アイコン・本文画像はPNG/JPEG/WebP/GIF/AVIFに対応します。

作品の「公開済み」は原稿の状態管理です。クラウド公開・同期・AI・SNS機能はMVPに含みません。

## テストと構成

`npm run test` はVitestのドメイン・保存・履歴・変換・書き出しテストを実行します。
`npm run test:e2e` はビルドしてから、専用ポート43179のプレビューサーバーを起動し、Chromiumで主要フロー・スマホ・タッチ・アクセシビリティ・1000ブロックを検証します。
既存のサーバーは再利用しません。`playwright-report/` にHTMLレポート、`test-results/` にスクリーンショット等が生成されます。

- `src/domain/`: 型・factory・schema検証・マイグレーション入口
- `src/stores/`: 状態管理・Undo/Redo・編集状態・設定
- `src/db/`: IndexedDB・バックアップ・自動保存
- `src/components/editor/`: 入力UIと並べ替え
- `src/renderer/`, `src/themes/`: エディタから独立した表示エンジンとテーマ
- `src/features/`: 作品・キャラ・エピソード・インポート・書き出し

`npm run check:phase -- <番号>` はbuild/test成功時のみTASKSの該当Phaseを完了にし、`IMPLEMENTATION_LOG.md` に結果を追記します。
開発用の仕様書は維持しています。JSON設計に省略されている表示項目は、関連仕様書で明示された任意フィールドとして扱います。

## 配布

`npm run build` で生成される `dist/` を静的HTTPサーバーに配置してください。
HashRouterと相対アセットパスを使うため、サブディレクトリ配信でもサーバー側のルート書き換えは不要です。
IndexedDB・crypto.randomUUIDを使用できる現行ブラウザーとHTTPSまたはlocalhostを使用してください。
`index.html` のファイル直接起動ではなくHTTP配信を利用します。書き出した単一HTMLは直接開けます。

配布ライセンスの検討内容は `LICENSE_REVIEW.md` を参照してください。

### GitHub Pages

公開先は `https://tetoriapot.github.io/kakkeko/`、リポジトリは `https://github.com/Tetoriapot/kakkeko` です。
GitHubのSettings → PagesでSourceを「GitHub Actions」に設定します。
`main`へのpush、またはActionsの「Deploy to GitHub Pages」から手動実行すると、lint・format・unit test・production build・E2Eの成功後に`dist/`を公開します。
公開処理と結果は `.github/workflows/pages.yml` とActionsの実行履歴で確認できます。

ローカル版から作品を移す場合は、ローカル版の設定画面で全作品JSONを出力し、公開先の「インポート」から取り込んでください。
ローカル版と公開先は保存場所が異なります。公開先で編集した作品も利用中のブラウザー内に保存され、GitHubへ送信されません。
